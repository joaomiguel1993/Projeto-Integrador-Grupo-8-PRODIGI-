COMANDOS GIT (GitHub)
Fluxo correto (equipa)
🔹 Quando TU fazes alterações:
git add .
git commit -m "mensagem"
git push
🔹 Quando os teus colegas querem atualizar:
git pull

👉 Isso traz o teu código para o PC deles

⚠️ MAS ATENÇÃO (muito importante)

Se eles tiverem alterações locais não commitadas, o git pull pode dar:

conflitos ❌

ou erros como o que viste

💡 Regra de ouro

Antes de dar pull, eles devem fazer uma destas:

👉 Opção 1 (segura)
git add .
git commit -m "trabalho local"
git pull
👉 Opção 2 (se não querem guardar o que fizeram)
git reset --hard
git pull
🔥 Resumo simples
Situação	Comando
Atualizar projeto	git pull
Enviar alterações	git push
Apagar alterações locais	git reset --hard
🧠 Dica de equipa (muito importante)

👉 Combina isto com o grupo:

“Antes de dar pull → commit ou reset”

“Não editar os mesmos ficheiros ao mesmo tempo”

🔹 git add .

👉 Adiciona todos os ficheiros para serem enviados

🔹 git commit -m "mensagem"

👉 Guarda uma “versão” do projeto
(ex: "update", "backend pronto")

🔹 git push

👉 Envia tudo para o GitHub

🔹 git push -u origin main

👉 Primeira vez que ligas ao GitHub

cria ligação ao branch main

🔹 git status

👉 Mostra:

git pull

👉 Isso faz:

vai ao GitHub

busca as alterações

atualiza o projeto loca

ficheiros alterados

se há coisas por enviar

🔹 git rm -r --cached venv

👉 Remove a pasta venv do Git (sem apagar do PC)

📁 COMANDOS DE NAVEGAÇÃO
🔹 cd backend

👉 Entra na pasta backend

🔹 cd ..

👉 Volta para a pasta anterior

🐍 COMANDOS PYTHON / BACKEND
🔹 pip install fastapi uvicorn

👉 Instala o backend (API)

🔹 pip install psycopg2

👉 Liga Python ao PostgreSQL

🔹 python -m uvicorn main:app --reload

👉 Liga o servidor backend

main → ficheiro main.py

app → variável do FastAPI

--reload → reinicia automaticamente

🗄️ COMANDOS BASE DE DADOS (PostgreSQL)
🔹 psql --version

👉 Ver se PostgreSQL está instalado

🔹 psql -U postgres -d projeto -f ficheiro.sql

👉 Executa ficheiro SQL

Exemplo:

psql -U postgres -d projeto -f backend/SQL/createTables.sql
